# 0009. Langfuse tracing is mandatory

## Context

An agent that answers customers needs traces to debug a wrong answer: which tool it called, what it received, what it cost. Optional tracing tends to be off exactly when something breaks. Traces can also leak customer data if exported carelessly.

## Decision

Every agent turn is traced to Langfuse, and startup fails with a clear error when the keys are missing, tracing is disabled or the authentication check fails. Locally Langfuse runs from the compose `observability` profile on our Postgres, with keys generated by a make target; the hosted demo uses Langfuse Cloud. Before export, two protections apply: session ids are pseudonymized with an HMAC keyed by a stable `LANGFUSE_SALT`, and customer names are masked in the span text.

## Consequences

- Every answer can be traced, and tests inject a fake tracer.
- Setup needs Langfuse keys even for a quick try; the local profile removes the signup.
- The salt must never change, or every pseudonymous session id changes with it.
- Name masking over-redacts surnames that are also common words, which we accept.

## Alternatives

- Optional tracing: simpler setup, but blind when it matters.
- Logging to files: no tool-call view and no cost breakdown.
