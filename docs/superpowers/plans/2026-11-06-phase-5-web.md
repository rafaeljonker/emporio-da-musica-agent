# Phase 5: API and frontend (login, warm-up, chat over SSE, `make up`, e2e) — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the evaluator can open one URL and do the whole demo. They log in, watch an honest warm-up, and chat with the phase 4 agent in paced pt-BR bubbles. They can also switch "Conversar como…" and read per-turn metrics. `make up` serves it locally on one port, and `make e2e` proves the flow in a browser.

**Architecture:**
- **API:** `emporio/api/` is a FastAPI app built by `create_app(agent, warmup, settings)`. It has:
  - a signed-cookie session (Starlette `SessionMiddleware`);
  - `/api/auth/*`, `/api/customers`, `/api/identity`, `/api/warm*`;
  - `/api/chat`, which runs the whole turn and then emits paced bubbles over FastAPI's native SSE.
  - It sees the agent only through the `ChatAgent` and `Warmup` ports in `support/application`.
- **Composition root:** `emporio/web.py` builds `create_web_app()` from `bootstrap.build_agent` and `bootstrap.build_warmup`. It mounts `frontend/dist` on the same origin.
- **Frontend:** `frontend/` is Vite + React + TS + Tailwind v4 + shadcn. There is no router: login, warm-up and chat are states of one shell. SSE is read with `fetch` + `eventsource-parser`. Pure logic is covered by Vitest, and the flow by Python Playwright in `e2e/`.
- **Fake model:** `EMPORIO_FAKE_MODEL=1` is a composition-root switch to a scripted model for e2e and dev. Langfuse stays on even then.

**Tech stack:**
- fastapi 0.162 (`fastapi.sse`), starlette 1.10 `SessionMiddleware`, itsdangerous 2.2, uvicorn 0.54, httpx 0.28;
- playwright 1.64 + pytest-playwright 0.10;
- vite 8 / react 19.3 / typescript 7.0 (fallback `~5.9`), tailwindcss 4.3 + `@tailwindcss/vite`, shadcn CLI 4.23, lucide-react, `@fontsource-variable/{fraunces,source-sans-3}`, eventsource-parser 4.1, vitest 5.1.

**Spec:** `docs/superpowers/specs/2026-11-05-emporio-agent-design.md` §5, §7.2.3, §7.3, §7.5, §7.7, §7.9 (phase 5 row), §7.14. **Research + owner decisions (binding):** `docs/research/phase-5.md`, including "Owner decisions (2026-11-06)". **Design (binding for copy and behavior):** `.design/projects/emporio-chat/design/{INDEX,screen-01-chat,screen-02-warmup,screen-03-login}.md`, `shared/*`, `.design/branding/emporio-da-musica/patterns/{STYLE.md,emporio-da-musica.theme.json,components/*}`, `.design/system/STACK.md`, and the UI copy table in `strategy/voice-and-tone.md`. **Backlog:** `.superpowers/sdd/2026-11-05-phase-4-agent/progress.md` (R9), `.superpowers/reviews/2026-11-05-pr-5/verdict.md` row 11 (eval cases), `.superpowers/reviews/2026-11-05-pr-2/verdict.md` rows 8–10 and 15.

  - `emporio.api` may import `emporio.support.application`, `emporio.support.domain`, `emporio.shared` and `emporio.config`.
  - A new forbidden contract keeps `emporio.api` away from every `*.infrastructure`, `emporio.{bootstrap,db,migrate,embeddings,ingest}`, `langchain*`, `langgraph`, `psycopg*` and `langfuse`.
  - `emporio.web` joins `emporio.bootstrap`/`emporio.cli` in the "Only infrastructure may use technical modules" forbidden list.
  - AGENTS.md's layer table is updated to match.
- **Identity:**
  - The session cookie holds only `{sid, customer_id}`. `sid` is always generated server-side (`secrets.token_urlsafe(16)`). The browser never sends a customer id with a message: `ChatIn` has `extra="forbid"`.
  - The customer is set only by `PUT /api/identity`, validated with `customer_exists`, and every switch rotates `sid`.
  - The thread id includes the session: `"{channel}:customer:{id}:{session}"` and `"{channel}:anon:{session}"`. The Langfuse session for an identified customer is `"{channel}:{pseudonym}:{session}"`, which keeps R8.
- **Auth:**
  - One demo user is read from env (`DEMO_EMAIL`, `DEMO_PASSWORD`) and compared with `hmac.compare_digest` on both fields.
  - The cookie is signed with `SESSION_SECRET` (≥ 32 chars): `same_site="strict"`, `https_only=SESSION_HTTPS_ONLY` (default true; `make up`/`dev`/`e2e` set false for `http://localhost`), `max_age` 8 h.
  - Bodies are JSON only: a non-`application/json` POST/PUT gets 415. There is no CORS middleware. Logout is a `POST`.
  - Credentials, cookies and request bodies are never logged.
- **Secrets:** only in `.env` (git-ignored) and Modal secrets. `.env.example` lists names only: `DEMO_EMAIL`, `DEMO_PASSWORD`, `SESSION_SECRET`, `SESSION_HTTPS_ONLY`, `EMPORIO_FAKE_MODEL`, `EMPORIO_FAKE_WARM_SECONDS`, `EMPORIO_FAKE_WARM_MODE`, `WARM_EXPECTED_SECONDS_GPU`, `WARM_EXPECTED_SECONDS_LOCAL`. `DEMO_USER` is renamed to `DEMO_EMAIL`. Never print or copy values.
- **Langfuse stays mandatory** for every real run, including `make up`. The fake model replaces only the chat model and the classifier. `make e2e` still needs `make langfuse-up`.
- **Owner decisions (2026-11-06):**
  - **Bubbles:** run the whole turn, then emit the bubbles paced with server-computed `delay_ms`. No token streaming.
  - **GPU warm-up:** one stage, "Ligando o modelo", until vLLM `/health` answers. No Modal stats.
  - **Local mode:** `PROVIDER=local` is phase 6, but the `local_cpu` screen is built now and driven by config.
  - **Bubble kinds:** text only. `kind` reserves `product | handoff`.
- **Copy:** pt-BR UI copy is taken verbatim from the design screens and the voice guide's UI copy table. Code and docs are in English. `lang="pt-BR"`.
- **Accessibility (WCAG 2.2 AA, from the design):**
  - `role="log"` transcript, with bubbles appended only when complete;
  - a `role="status"` typing indicator outside the log;
  - one persistent `role="status"` region in `<main>`. Only `failed` and login errors are `role="alert"`.
  - Send uses `aria-disabled` (never `disabled`). Focus never jumps into the log, and a selector change never moves focus.
  - Targets ≥ 44 px (links ≥ 24 px). Units are rem.
  - Reflow at 320 px and the `max-height: 480px` rule.
  - `prefers-reduced-motion` drops the fade and the dot pulse, but not the pacing.
- **Per-process state** (thread locks, warm state, rate limits) is in memory. Each piece is marked with a `ponytail:` comment naming the multi-container ceiling and the upgrade (advisory lock, one-row warm table).

## Review Focus
1. **The same customer picked in two sessions (two evaluators, or two tabs after a switch).** Expected: two threads, so neither sees the other's turns. Tests: Task 3 `test_same_customer_two_sessions_get_different_threads` and `test_identity_switch_rotates_sid`.
2. **The browser tries to choose identity** (a `customer_id` in the chat body, or a tampered cookie). Expected: 422 for the body field and 401 for the cookie, with no turn run. Tests: Task 2 `test_chat_rejects_customer_id_in_body` and Task 1 `test_tampered_cookie_is_unauthenticated`.
3. **Double send or a second tab while a turn runs.** Expected: the second request gets 409 and the thread is not interleaved. A lock left behind by a dropped connection heals. Tests: Task 2 `test_concurrent_turn_on_same_thread_gets_409` and `test_stale_lock_is_reclaimed`.
4. **The turn fails** (model down, graph error). Expected: the stream ends with `error {partial: false}`, with no bubble of the error text, no `metrics` event and the lock released. The UI offers "Manda de novo?". Tests: Task 2 `test_failed_turn_emits_error_and_releases_lock` and Task 7 Vitest `error before any bubble is not partial`.
5. **A GPU cold start longer than Modal's 150 s request limit.** Expected: a 303 or a timeout means "still starting". `failed` comes only after the deadline, and a retry keeps `started_at`. Tests: Task 6 `test_probe_treats_303_and_timeout_as_starting`, `test_probe_fails_after_deadline` and `test_retry_keeps_started_at`.

### Task 2: `/api/chat` over SSE

**Files:**
- Create: `backend/src/emporio/api/chat.py`
- Modify: `support/domain/bubbles.py`, `support/application/{ports,handle_message}.py`, `support/infrastructure/agent/runner.py` (sets `failed`), `api/guards.py` (`ThreadLocks`)
- Test: `backend/tests/unit/support/test_bubbles.py`, `test_handle_message.py` (extend), `backend/tests/unit/api/test_chat.py`

**Interfaces:**
- `pace_bubbles(bubbles: Sequence[str]) -> tuple[int, ...]`:
  - bubble 1 is `0`;
  - each later bubble is `clamp(400 + 22 * len(text), 700, 2400)`;
  - the running total is capped at `3000`, so the bubble that reaches the cap gets what is left (possibly 0).
- `TurnMetrics` gains `failed: bool = False`, which is not persisted. The runner sets it on an exception, a recursion error or an empty answer.
- `Reply` gains `metrics: TurnMetrics | None = None` and `failed: bool = False`. `HandleMessage` fills both, and a blank text gives `failed=True`.
- `ThreadLocks(stale_after: float = 300.0)`:
  - `try_acquire(thread_id: str) -> bool` and `release(thread_id: str) -> None` (a dict of monotonic timestamps under one `threading.Lock`);
  - a lock older than `stale_after` is reclaimed;
  - mark it with `# ponytail: in-process lock, pg_try_advisory_lock if the API runs >1 container`.
- `action_label(tools: Sequence[str]) -> str`:
  - `search_products|get_product|recommend_products|list_active_promotions` → "busca no catálogo";
  - `calc_installments` → "cálculo de parcelas";
  - `list_my_orders|get_order_status` → "consulta de pedido";
  - `check_return_eligibility` → "consulta de troca";
  - `store_now` → "horário da loja";
  - `search_policies` → "consulta às políticas";
  - none → "sem ferramenta".
  - Distinct labels in first-seen order are joined with " + ".
- `POST /api/chat`:
  - body `ChatIn(text: str)` with strip, `min_length=1`, `max_length=1000`, `extra="forbid"`;
  - `require_json`, `require_session`, `SlidingWindow(20, 600)` per `sid` (429);
  - `ThreadLocks` per thread id (409 `{"detail": "turn_in_progress"}`, checked before the stream starts);
  - `response_class=EventSourceResponse` over a sync generator, with `ChannelIdentity("web", session.customer_id, session.sid)`.
- **Event contract.** The stream ends with exactly one `done` or `error`, and the lock is released in the generator's `finally`.
  - `typing` `{}`.
  - `bubble` `{"kind": "text", "text": str, "delay_ms": int}`.
  - `metrics` `{"input_tokens", "output_tokens", "ms_model", "ms_guard", "ms_llm", "ms_tools", "cost_brl", "cost_basis", "action"}`:
    - the token and `ms_*` values are ints, and `ms_model` = `ms_total`;
    - `cost_brl` is a 4-decimal string or `null`;
    - `cost_basis` is "Estimado pelo preço de lista do provedor" when priced, else "Custo de GPU ainda não medido".
  - `done` `{"trace_id": str}`.
  - `error` `{"partial": bool}`. It is sent when `reply.failed` (`partial=false`), or on an exception after ≥ 1 bubble (`partial=true`).

### Task 6: warm-up backend

**Files:**

**Interfaces:**
- `ProbeWarmup(probe: Callable[[], bool], mode: WarmMode, expected_seconds: int, reply_p50: Callable[[], float | None], *, stage: WarmStage = SERVER_STARTING, deadline_seconds: float = 600, interval_seconds: float = 2, clock: Callable[[], datetime] = …)`:
  - `start()` is single-flight: one daemon thread per process. It sets `started_at` on the first call, and on a retry after `failed` it restarts the thread but **keeps** `started_at`.
  - `status()` starts the probe if it never ran. That covers an API restart under a live session.
  - `elapsed_seconds` is server-computed and freezes at ready.
  - A probe exception counts as `False`.
  - Past `deadline_seconds` the stage becomes `failed`.
- `vllm_health_probe(base_url: str, api_key: str, timeout: float = 10) -> Callable[[], bool]`:
  - `GET {base_url minus /v1}/health` with a bearer token and `follow_redirects=False`;
  - true only on 200, so 303, 503 and timeouts are false.
- `PgMetricsStore.reply_p50_seconds(limit: int = 50) -> float | None`: `percentile_cont(0.5)` of `ms_total` over the last `limit` rows, in seconds.
- `bootstrap.Agent` gains `reply_p50_seconds: Callable[[], float | None]` (`PgMetricsStore.reply_p50_seconds`); `web.py` passes it to `build_warmup`.
- `build_warmup(settings: Settings, reply_p50: Callable[[], float | None]) -> Warmup`:
  - gemma → `ProbeWarmup(vllm_health_probe(...), MODAL_GPU, settings.warm_expected_seconds_gpu)`;
  - gemini/openai/anthropic → `ReadyWarmup(PROVIDER_API, reply_p50)`;
  - fake with `EMPORIO_FAKE_WARM_SECONDS > 0` → `ProbeWarmup(<elapsed ≥ N>, settings.fake_warm_mode, …)`, where `local_cpu` uses stage `model_loading`.
- New settings:
  - `warm_expected_seconds_gpu: int = 180` (the measured 175 s; phase 6 re-measures);
  - `warm_expected_seconds_local: int = 120`;
  - `fake_warm_seconds: int = 0`;
  - `fake_warm_mode: WarmMode = MODAL_GPU`.
- **Routes:**
  - `POST /api/warm` → `start()`;
  - `GET /api/warm/status` → `status()`;
  - both require a session; the payload is the same as `WarmStatus.to_json()`;
  - `GET /api/warm/expected` → `{"mode", "expected_seconds"}`. It is public and starts nothing, since it is the login note's `{N}`.
